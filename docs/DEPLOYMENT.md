# Deploying the public demo to Render

This repo contains a [Render Blueprint](../render.yaml) that creates everything needed for a
public, interactive demo of the Property Management Platform API:

- a managed PostgreSQL database,
- the NestJS API running in Docker,
- automatic migrations and idempotent demo seeding on every boot,
- Swagger UI at `/api/docs` as the demo interface.

The integrations run in **mock mode** (`SMS_MOCK=true`, `TELEBIRR_MOCK=true`), so no external
credentials are required.

---

## Deploy in 5 minutes

1. Push this repo to GitHub (or fork it to your own account).
2. Log in to [Render](https://dashboard.render.com/) and click **New → Blueprint**.
3. Connect the GitHub repo. Render detects `render.yaml` at the repo root.
4. Give the blueprint a name (for example `property-management-demo`) and click **Apply**.
5. Wait for the web service to report **Live**. The first build/deploy takes a few minutes.

Render will create these two resources:

| Resource | Name | Purpose |
|---|---|---|
| Web service | `property-management-demo-api` | API + Swagger |
| PostgreSQL | `property-management-demo-db` | Demo data |

### URLs

Once the service is live:

| What | URL |
|---|---|
| Swagger demo | `https://property-management-demo-api.onrender.com/api/docs` |
| Health check | `https://property-management-demo-api.onrender.com/health` |
| REST base | `https://property-management-demo-api.onrender.com/api/v1` |

> The service name determines the URL. If Render appends a suffix because the name is taken,
> use the actual URL shown in the dashboard and update `BASE_URL` in the service's environment.

## Demo walkthrough

Every seeded account uses the password `Demo@12345`.

| Role | Phone | Email |
|---|---|---|
| Admin (Possible Technology) | `+251911000001` | `admin@possibletech.et` |
| Ethio Telecom (payments) | `+251911000002` | `payments@ethiotelecom.et` |
| Owner | `+251911000003` | `owner@demo.et` |
| Manager (works for the owner) | `+251911000004` | `manager@demo.et` |
| Tenant | `+251911000005` | `tenant@demo.et` |

A good demo path:

1. Open Swagger and call `POST /auth/login` with the tenant account.
2. Click **Authorize** in Swagger and paste the returned `accessToken`.
3. Browse `GET /listings` to see available units.
4. Log in as the owner and open `GET /dashboard` to see occupancy and rent figures.
5. Log in as the admin to see platform-wide oversight and the audit log.

Example login:

```bash
curl -X POST https://property-management-demo-api.onrender.com/api/v1/auth/login \
  -H 'Content-Type: application/json' \
  -d '{"identifier":"+251911000005","password":"Demo@12345"}'
```

In Telebirr mock mode, payment checkout links point back to the demo API, so you can complete
a payment callback without any real money or credentials.

## What the Blueprint configures

- **Build:** `apps/backend/Dockerfile` (multi-stage, Node 20 + OpenSSL + Ethiopic PDF font).
- **Start command:** `npx prisma migrate deploy && node dist/database/seeds/seed.js && node dist/main.js`.
- **Secrets:** `JWT_SECRET`, `JWT_REFRESH_SECRET` and `DATA_ENCRYPTION_KEY` are generated by Render.
- **Database URL:** injected from the managed Postgres instance with `fromDatabase`.
- **Public URL:** `BASE_URL` is set to the Render service URL so generated links point to the demo.
- **CORS:** `*` for the public demo. Restrict this before using the API in a real product.

## Notes and troubleshooting

- **Free plan cold starts:** Render free web services sleep after inactivity. The first request
  after a pause can take ~30–60 seconds. Ping `/health` first to wake it up.
- **Free Postgres expiry:** Render's free managed databases expire after 30 days. Upgrade to
  Starter if you need the demo to stay online permanently.
- **First deploy shows 503:** check the service logs. The API only becomes healthy after
  migrations and seeding finish.
- **Seed is idempotent:** redeploys and restarts do not duplicate demo data.
- **Don't put real credentials in the Blueprint.** Use Render environment variables/dashboard
  secrets for anything sensitive.

## Run the same demo locally

Everything runs in Docker; no local Node or Postgres install is required.

```bash
cp .env.example .env
docker compose up -d --build
docker compose logs -f backend
```

Then open <http://localhost:4100/api/docs>. See the [README](../README.md) for the full feature
list and test commands.
